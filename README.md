# ai-dev-harness-kit

여러 AI 코딩 에이전트(Claude Code · Codex · Gemini CLI · Cursor)를 오가며 개발할 때,
**규칙 준수와 인수인계를 문서가 아니라 기계로 강제하는** 최소 하네스.

의존성 없음 — `bash` + `git`만 있으면 됩니다. 전체 800줄 미만.

---

## 왜 만들었나

AI에게 개발을 맡길 때 반복되는 문제가 있습니다.

1. **"완료했습니다"를 검증할 방법이 없다** — AI는 항상 자신 있게 보고합니다.
2. **다음 AI가 앞선 작업을 모른다** — 매번 처음부터 파악하느라 컨텍스트를 태웁니다.
3. **AGENTS.md에 규칙을 써도 안 지킨다** — 문서로 부탁하는 방식의 한계입니다.

3번에 대한 실측 근거가 있습니다. 규칙 준수 연구(arXiv 2607.26819)에서
에이전트가 규칙 파일을 자발적으로 읽는 비율은 **3.5%**였고,
**인수인계 규칙 준수율은 테스트한 네 모델 전부 0%**였습니다.

반대로 "검증을 실행하라"처럼 **작업에 단계를 추가하는** 지시는 최대 100% 따랐습니다.
이 비대칭이 이 킷의 설계 근거입니다.

> **인수인계는 훅으로 강제하고, 검증은 명령으로 요청한다.**

## 설치

```bash
git clone https://github.com/voodoosim/ai-dev-harness-kit ~/kit

cd ~/dev/내프로젝트
~/kit/kit-init.sh

git add .githooks AGENTS.md CLAUDE.md .cursorrules GEMINI.md docs STATUS.md .gitignore
git commit -m "chore: 하네스 도입"
```

설치 상태 점검은 `~/kit/kit-init.sh --check`, 스크립트만 최신본으로 교체는 `--update`.

## 구성

| 스크립트 | 역할 | 실행 시점 |
| --- | --- | --- |
| `kit-init.sh` | 배포 · 심볼릭 링크 · 훅 설치 | 프로젝트당 1회 |
| `status-sync.sh` | STATUS.md 자동 구역 갱신 | 커밋마다 (훅) |
| `gate-check.sh` | 완료 조건 검증 → exit code | 작업 종료 선언 전 |
| `dashboard-roll.sh` | 전 프로젝트 집계 → DASHBOARD.md | 매일 / 주간 |
| `test.sh` | 37개 자동 테스트 | 킷 수정 후 |

### 흐름

```
작업 → 커밋 ─(post-commit)→ status-sync   자동 구역 갱신
                                 ↓
       사람이 "다음 할 일" 작성 ──┘
                                 ↓
                            gate-check    6항목 exit code 판정
                                 ↓ exit 0
                        echo G4 > .gate   ← 사람이 승격 (자동 아님)
                                 ↓
                          dashboard-roll  전 프로젝트 🟢🟡🔴
```

## gate-check — 완료의 정의를 exit code로

```bash
./gate-check.sh
```

| # | 검사 | 비고 |
| --- | --- | --- |
| 1 | 빌드 | Node·Python·Go 자동 감지 |
| 2 | 테스트 | 패스트트랙에선 경고, 전체 게이트에선 실패 |
| 3 | 린트 | `.pre-commit-config.yaml` 있으면 위임 |
| 4 | 문서 필수 섹션 | 목표 / 범위 / 완료 조건 |
| 5 | **인수인계 내용** | "다음 할 일"이 비면 실패 |
| 6 | 커밋 메시지 | 브랜치 전체 검사, commitlint 있으면 위임 |

5번이 이 도구의 핵심입니다. `status-sync`가 자동 구역을 채워주기 때문에
"STATUS.md가 최신인가"만 보면 항상 통과합니다. 그래서 **사람이 써야 하는 칸이
비어 있는지**를 검사합니다.

실패하면 완료 조건과 게이트 정의를 그 자리에서 출력합니다.
이 내용을 AGENTS.md에 넣지 않은 이유는 아래 설계 원칙 1번에 있습니다.

```bash
./gate-check.sh --skip lint      # 개별 검사 생략
./gate-check.sh --gate G4        # 게이트 지정
./gate-check.sh --no-delegate    # 외부 도구 위임 끄기
./gate-check.sh --stats          # 측정 지표
```

## 두 가지 모드

| | 패스트트랙 (기본) | 전체 게이트 |
| --- | --- | --- |
| 켜는 법 | 아무것도 안 함 | `echo G0 > .gate` |
| 검사 | 빌드·테스트·린트·인수인계·커밋 | + 문서 템플릿 |
| 쓸 곳 | 솔로·탐색·소규모 작업 | 배포 대상·다인 협업 |

솔로 개발이나 요구사항이 유동적인 작업에 정식 게이트는 과잉이라는 것이
실무 가이드의 일관된 권고입니다. 그래서 **기본값을 가벼운 쪽으로** 두었습니다.

게이트: `G0 조사 → G1 설계 → G2 분할 → G3 구현 → G4 출시가능`

## STATUS.md — 인수인계 문서

커밋할 때마다 훅이 자동 구역을 갱신합니다. **수동 구역은 절대 건드리지 않습니다.**

```markdown
<!-- status-sync:auto:start -->     ← 기계가 씀
| 현재 게이트  | G3 |
| 담당 AI      | Claude Code |
| 마지막 작업  | feat: 결제 모듈 |
| 마지막 검증  | 통과 (이후 커밋 있음 — 재검증 필요) |
<!-- status-sync:auto:end -->

## 수동 기록 (다음 AI에게 넘기는 내용)   ← 사람이 씀
### 다음 할 일
### 차단 요인
```

담당 AI는 `CLAUDECODE`·`CURSOR_TRACE_ID`·`GEMINI_CLI`·`CODEX_SANDBOX` 환경변수로
자동 감지하며, `AI_AGENT=Codex ./status-sync.sh` 로 직접 지정할 수도 있습니다.

## 효과 측정

```bash
./gate-check.sh --stats
```

커밋별 **첫 시도 통과율**을 보여줍니다. 오르면 작동하는 것, 제자리면 절차만 늘어난 것.

측정 기능을 넣은 이유: METR 무작위 대조 실험에서 개발자들은 AI로 **19% 느려졌는데
20% 빨라졌다고 느꼈습니다**(39%p 격차). 도구의 효과를 느낌으로 판단하면 안 됩니다.
이 킷도 예외가 아닙니다.

## 설계 원칙

**1. AGENTS.md는 짧게 — 절차는 실패 메시지로**

`.cursorrules`·`GEMINI.md`는 AGENTS.md 심볼릭 링크, `CLAUDE.md`는 `@AGENTS.md` import.
기본 템플릿은 **15줄**입니다.

ETH Zurich 연구(2026-02)에서 컨텍스트 파일은 작업 성공률을 오히려 2~3% 낮추고
토큰 비용을 20% 이상 올렸습니다. 원인은 에이전트가 무시해서가 아니라 **너무 성실히
따르기** 때문입니다 — 오타 하나 고치는 작업에도 게이트 표 전체를 제약으로 처리합니다.

그래서 절차 규칙은 AGENTS.md가 아니라 `gate-check.sh` 실패 출력에 넣었습니다.
**위반한 순간에만 나타나는 just-in-time 지시**입니다.

**2. 훅은 저장소에 커밋**

`.git/hooks`는 git이 추적하지 않아 클론하면 사라집니다.
`.githooks/` + `core.hooksPath`를 쓰고, 클론 시 전파되지 않는 설정값은
`gate-check` 실행 시 자동 복구합니다.

**3. 기존 도구 우선**

commitlint·pre-commit이 있으면 위임하고, 없을 때만 자체 검사합니다.
빌드·테스트·린트는 성숙한 도구가 더 잘합니다. 이 킷의 고유 가치는 4·5번 검사입니다.

**4. 자동화하지 않는 것**

게이트 승격(`.gate`)과 "다음 할 일" 작성. 둘 다 사람의 감독 지점입니다.
여기까지 기계가 하면 "AI가 스스로 완료 선언하고 스스로 통과시키는" 원래 문제로 돌아갑니다.

## 알려진 한계

- **효과는 아직 검증되지 않았습니다.** 스크립트가 의도대로 동작하는 것은 테스트로
  확인했지만, 실제 개발 결과의 편차를 줄이는지는 `--stats` 숫자가 쌓여야 압니다.
  그전까지 이 킷은 가설입니다.
- `core.hooksPath`는 클론에 전파되지 않습니다 (첫 `gate-check.sh` 실행 시 자동 복구).
- 여러 에이전트가 **동시에** 커밋하는 경우의 경합은 테스트하지 않았습니다.
- Windows는 WSL 또는 Git Bash 필요.
- 훅은 결정론적 지점에만 걸립니다. "이 설계가 좋은가" 같은 판단은 여전히 사람 몫입니다.
